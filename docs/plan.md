# 實作計畫

## 目標與驗收條件

- 為 WPF 紙張排版畫布加入復原／重做，支援 `Ctrl+Z`／`Ctrl+Y` 與工具列操作。
- 納入目前的手動編排動作：移動、拖曳重排、旋轉、刪除、清空與重新命名。
- 復原後必須保留紙張順序、旋轉角度、選取狀態與匯出用檔名；重做後需還原相同結果。
- 將 `DESIGN.md`、`spec.md` 與本文件改為目前 C# 12／.NET 8／WPF 架構，不再保留 Python Web UI 的現行規格描述。

## 不做範圍

- 不將 Office／圖片轉檔的非同步匯入流程納入復原歷史，避免重複觸發 COM 轉檔或誤刪暫存檔。
- 不新增跨工作階段的專案檔或自動儲存功能。
- 不調整 PDF 向量合成、Office COM 隔離及縮圖快取的既有行為。

## 現況與限制

- 畫布狀態集中於 `MainViewModel.Pages`，頁面以 `PaperItem` 表示。
- 目前可在 `MainViewModel` 內完成所有手動編排，適合以狀態快照實作歷史紀錄，不需更換 MVVM 架構。
- PDF 匯出需維持 PdfSharp 原始頁面抽取與旋轉矩陣累加，歷史紀錄不得以縮圖重建頁面。

## 已確認決策

- 每次成功的手動編排動作保留一份前置畫布快照；執行復原／重做時以快照復原原有 `PaperItem` 物件。
- 快照保存順序、旋轉、選取狀態與 `SourceFileName`，不複製縮圖或來源檔案。
- 只有畫布實際變動時才新增歷史紀錄；新的編排動作會清空重做歷史。

## 風險與因應

- 清空／刪除後的頁面仍需可被復原：快照保留原始 `PaperItem` 參考，僅暫時自集合移除。
- 連續多步移動不應產生錯誤順序：以每次公開編排命令作為一筆歷史紀錄。
- 載入縮圖中的項目仍可能更新：快照不管理縮圖欄位，保留背景載入任務的既有行為。
